# Inspection Document Parser API

![tests](https://github.com/USERNAME/inspection-doc-parser-api/actions/workflows/ci.yml/badge.svg)

**Live demo:** https://YOUR-APP-NAME.azurewebsites.net · **API docs:** https://YOUR-APP-NAME.azurewebsites.net/docs

A small web service that turns dense inspection-report PDFs into structured JSON:

- **Tables**, including borderless *Element / Rating / Comment* tables laid out with whitespace instead of grid lines
- **Fillable form-field values**, read from the PDF's own form structure instead of guessed from text
- **Clean text**, with banners and header blocks that repeat on every page stripped out

It's the document-parsing stage of my [inspection QA model](https://github.com/USERNAME/inspection-qa-model), packaged as a deployable API. Engineering reports are mostly PDFs, and the hard part of automating anything on top of them is reliably getting the data out.

## Try it

Open the live demo and click **Try the sample report**. The sample is a synthetic three-page inspection report with fillable rating fields, a borderless table, a ruled table, and a banner repeated on every page. All of its data is invented.

```bash
# Parse your own PDF
curl -F "file=@report.pdf" "https://YOUR-APP-NAME.azurewebsites.net/parse?detail=tables"

# Parse the bundled sample
curl "https://YOUR-APP-NAME.azurewebsites.net/sample?detail=tables"
```

Abridged response:

```json
{
  "summary": {
    "pages": 3, "tables": 2, "acroform_fields": 5,
    "boilerplate_lines_removed": 3, "parse_seconds": 0.07
  },
  "acroform_fields": { "deck_rating": "6", "substructure_rating": "5", "culvert_rating": "N" },
  "tables": [
    { "page": 1, "n_rows": 6, "n_cols": 3,
      "cells": [ { "row": 0, "col": 0, "text": "Element / Component" }, "..." ] }
  ]
}
```

## Endpoints

| Method | Path | What it does |
|---|---|---|
| `POST` | `/parse` | Parse an uploaded PDF (max 10 MB, 30 pages). `?detail=full` (default) returns everything; `?detail=tables` returns tables and form fields only. |
| `GET` | `/sample` | Parse the bundled synthetic sample report. |
| `GET` | `/sample.pdf` | Download the sample to compare against the output. |
| `GET` | `/health` | Health check. |
| `GET` | `/docs` | Interactive API documentation (generated by FastAPI). |

## How it works

**Text and form fields.** pdfplumber extracts text in visual reading order, which keeps the labels on dense multi-column forms from running together. Form values come from the PDF's AcroForm structure, the same data a PDF viewer shows in the fillable boxes.

**Boilerplate removal.** Any line that appears near-verbatim on at least 40% of a document's pages is treated as a repeated banner or header and stripped before anything else sees it. Lines shorter than 15 characters are exempt, so short field values aren't deleted by coincidence.

**Ruled tables.** These go through pdfplumber's line-based table detection.

**Borderless tables.** pdfplumber's text-based table strategy treats any page of left-aligned text as one big grid. It slices words in half and pulls banners into the "table." I replaced it with a column-alignment detector:
1. Group words into lines, and merge words separated by small gaps (under 15 pt) into phrases.
2. Start a candidate table at any line with two or more phrases, using their x-positions as column anchors.
3. Extend it downward while every phrase on each following line starts within 6 pt of an anchor.
4. Keep runs of at least 3 multi-column lines, and drop trailing single-cell lines such as a note under the table.

**Safety limits.** The service enforces a 10 MB size limit, a 30-page limit, and a check of the PDF signature bytes. A guard also skips table detection on CAD and plan sheets, which can contain thousands of vector objects. Uploads are written to a temporary file only for the duration of the request and deleted immediately, and a test verifies that nothing is left behind.

## Deploy to Render (free, no credit card)

Push this repository to GitHub, then in Render choose **New → Web Service**, connect the repository, and use:

| Setting | Value |
|---|---|
| Language | Python 3 |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| Instance Type | Free |
| Environment variable | `PYTHON_VERSION` = `3.12.7` |
| Health Check Path (Advanced) | `/health` |

Or choose **New → Blueprint** and select the repository; `render.yaml` holds the same settings. Free services sleep after 15 minutes without traffic, and the first request after that takes about a minute.

## Deploy to Azure App Service (free tier)

Prerequisites: an [Azure account](https://azure.microsoft.com/free/) and the [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli).

```bash
az login

# 1. A resource group to hold everything (easy to delete later)
az group create --name inspection-parser-rg --location eastus

# 2. Create the app and deploy this folder. The name must be globally unique;
#    it becomes https://<name>.azurewebsites.net
az webapp up --name YOUR-APP-NAME --resource-group inspection-parser-rg \
  --runtime "PYTHON:3.12" --sku F1 --location eastus

# 3. Tell App Service how to start a FastAPI app
az webapp config set --name YOUR-APP-NAME --resource-group inspection-parser-rg \
  --startup-file "gunicorn -w 2 -k uvicorn.workers.UvicornWorker --bind 0.0.0.0:8000 --timeout 120 app.main:app"
```

Open `https://YOUR-APP-NAME.azurewebsites.net`. The first request after a deploy or an idle period can take 30–60 seconds while the app starts.

To redeploy after changes, run the `az webapp up` command from step 2 again. To view logs: `az webapp log tail --name YOUR-APP-NAME --resource-group inspection-parser-rg`. To delete everything: `az group delete --name inspection-parser-rg`.

**Free-tier (F1) limits:** 60 CPU minutes per day, 1 GB of memory, and the app sleeps when idle. That's plenty for a portfolio demo. The Basic B1 tier removes these limits for a small monthly cost.
